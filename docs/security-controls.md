# Security control register

This is a list of security controls this repo ships or relies on, not every one of them. A
reviewer handed a security-bearing diff checks it against this list as well as its own
checklist and whatever the dispatching brief said. A control missing here is a gap in the
register, not a reason to skip a check. Each row gives the invariant the control holds, the files
that carry it out, and the tests that pin it.

Keep it current. A new control gets a row in the same change that adds it. A control that is
renamed, moved or retired gets its row edited or removed in that change. The test in
`test/security-controls.test.ts` fails when a cited file or test no longer exists, so a stale
path shows up as a red build. It cannot tell whether the invariant sentence is still true, so a
change to a control's behaviour needs a human to reread its row.

Paths are repo-relative. Only backticked paths in the last two columns are checked.

| Control | Invariant | Implementing files | Pinning tests |
|---|---|---|---|
| Identity gate, commit | A commit is refused when its staged content, pending author or committer, or branch name carries a declared name, email, username or hostname. A declared but unreadable identity file refuses too. | `core/claude/hooks/pre-commit`, `core/claude/hooks/identity-patterns.sh` | `test/identity-gate.test.ts`, `test/pre-commit.test.ts` |
| Identity gate, push | A push is refused when any commit, commit message, tag object or blob in the pushed range carries a declared name or email, or the derived workstation username or hostname. | `core/claude/hooks/pre-push`, `core/claude/hooks/identity-patterns.sh` | `test/identity-gate.test.ts` |
| Personal-term gate | Opt-in per clone, through the local git config `harness.personalTermsFile`. Where a clone opts in, a commit or push carrying a string from that list is refused, and a missing, empty or malformed list refuses rather than checking nothing. Where it is unset, the channel is skipped. | `core/claude/hooks/identity-patterns.sh`, `core/claude/hooks/pre-commit`, `core/claude/hooks/pre-push` | `test/personal-term-gate.test.ts` |
| Local secret scan | A commit is refused when staged content holds a provider-shaped token or private key. The scan fails closed when `grep` cannot run or a canary is not found, and never prints the match. | `core/claude/hooks/pre-commit` | `test/pre-commit.test.ts` |
| CI secret scan | A pull request's commit range is either scanned by Gitleaks or the job fails. A range that cannot be resolved never passes as clean. | `.github/workflows/test.yml`, `.gitleaks.toml` | `test/secret-scan-ci.test.ts` |
| No AI attribution | A commit message carrying a co-author trailer or other AI attribution is refused, whoever or whatever made the commit. | `core/claude/hooks/commit-msg` | `test/commit-msg.test.ts` |
| Worktree isolation | A dispatch of an agent that cannot be proven read-only is denied unless it is isolated or carries a written override with a reason, and an isolated write dispatch is denied unless its prompt carries a `BASE-SHA` line. The `tools` frontmatter key is read case-sensitively, as Claude Code reads it. When the project root and the session folder are both provably not a git repository, the dispatch is allowed with a note, since no worktree can exist there, and any other probe answer keeps the denial. An agent that declares a scratch write scope still needs isolation, and trusting it is deferred to #312. | `core/claude/hooks/agent-worktree-gate.ts`, `core/claude/hooks/agent-name.ts` | `test/agent-worktree-gate.test.ts`, `test/agent-name.test.ts` |
| Scratch write scope | An agent declaring a scratch write scope can write only inside a scratch folder. Inside the project root that is `.claude/scratch` and nothing else, reached by the project's own path, so a link, junction or short-name route to a project file is never scratch. Outside the project root it is a folder named scratch, scratchpad or .scratch, judged by the resolved path, that does not contain the project root. A path that cannot be resolved is not scratch, and long-path and UNC spellings are refused outright. The gate covers Write, Edit and the notebook path of NotebookEdit. Every other file write is denied before the permission system runs. | `core/claude/hooks/agent-write-scope.ts`, `core/claude/hooks/write-scope-parse.ts`, `core/claude/hooks/agent-name.ts` | `test/agent-write-scope.test.ts`, `test/agent-name.test.ts` |
| Bash tripwire (opt-in) | Where a project installs it with `-IncludeBashTripwire`, a Bash command that deletes a root, home or drive directory recursively is denied. A recursive force delete of a `.git` directory or a bare variable, a `git push` with force, a download piped into a shell, and a read of an ssh private key, `.env` file, `secrets/` file, `gh auth token` or `op read` each prompt, including in bypass mode. The hook returns ask, deny or no decision and never allow, and malformed input, a non-Bash payload, an unbalanced command and a scanner error all end in no decision. It runs locally with no network. It reads command text and does not expand variables or resolve paths, so it is friction against accidents, not a sandbox. Without the switch the script and its registration are absent, and `-Audit` lists the script as `not-installed (opt-in)` without counting it. | `core/claude/hooks/bash-tripwire.ts`, `core/claude/templates/settings.hooks.json`, `install/Install-Harness.ps1` | `test/bash-tripwire.test.ts`, `test/harness-standdown.test.ts`, `install/Install-Harness.Tests.ps1` |
| Untrusted content boundary | Every agent definition carries the same untrusted-content block, so none quietly drops it. | `core/claude/templates/untrusted-content-boundary.template.md` | `test/untrusted-block-identity.test.ts` |
| Account export scrub | The account export refuses to finish when any payload file or path carries the workstation username, a declared name or email, or a personal term. | `install/Export-Account.ps1`, `install/AccountShared.ps1` | `install/Export-Account.Tests.ps1`, `install/Account-Hooks.Tests.ps1` |
| Account payload matches export | Opt-in per clone, through the local git config `harness.preCommitChain`. Where the exporting workstation's clone opts in, a commit staging any `account/claude/` path is refused unless every staged path, deletions included, has the blob a fresh export of the account source would stage, compared through git's filters. A missing account source or `pwsh`, a missing exporter beside the check, a failed export, and a staged path git must quote all refuse. The export is hashed with `git add --force`, so no ignore rule hides an exported file. The check and its exporter run from an installed copy in the hook directory, never from the work tree, and the chain point refuses a value that is a path or names a script missing from that directory. The chained script and the exporter run with the same exposure as the installed `pre-commit` beside them: a branch that tracks files under `.claude/hooks/` replaces them on checkout, switch, merge or pull, and re-running the installer restores them. File mode and object type (100644, 100755, 120000) are compared along with content, and on a checkout with `core.filemode` false the modes HEAD tracks are the baseline, as they are for `git add`. A commit staging no payload path is never refused. No output carries file contents. | `install/check-account-payload.sh`, `core/claude/hooks/pre-commit` | `test/account-payload-check.test.ts`, `test/pre-commit.test.ts` |
| Account retire-list path check | The account installer renames a receiver's file only when the listed path is a relative file path under rules, agents, skills or hooks, checked against an allowlist before any rename. A path that climbs with `..`, is absolute, drive-qualified or written with backslashes, or ends in a line feed is refused. So is a path whose parent resolves outside that tree through a link, and one that is a directory or a link to one. A list that cannot be read or parsed refuses, and so does a payload that still carries a listed path. Nothing is renamed on any refusal, and a rename never overwrites. | `install/Install-Account.ps1`, `install/account-retired.json`, `install/AccountShared.ps1` | `install/Install-Account.Tests.ps1` |
| Installer sidecar protection | The per-machine sidecar file the installer writes is never written into a target repo while git does not ignore it, even when the target's ignore file predates the sidecar. The installer warns instead, and a copy that is already tracked is left in place with a warning. | `install/Install-Harness.ps1` | `test/gitignore-sidecar-protection.test.ts` |
| Hard-dependency refusal | An install refuses before its first write when a dependency that the kernel or a chosen layer marks hard is missing or below its minimum version. A probe that is not on PATH, exits non-zero, times out or prints no version counts as missing. A declined install of a hard dependency refuses too. Nothing is installed without `-InstallDeps`. | `install/Deps.ps1`, `core/claude/deps.json`, `install/Install-Harness.ps1`, `install/Install-Account.ps1` | `install/Install-Harness.Tests.ps1`, `install/Install-Account.Tests.ps1` |
| Pinned dependency installs | Every install command is an argument list built from winget, apt or npm fields that the manifest check holds to an exact version and a package-name pattern, so a range, a tag or a flag-shaped name never reaches a command line. Git on Linux is the one named exception. It installs through apt unpinned (operator ruling 2026-11-12, #310), declared with an `unpinned` reason that the check accepts only on an apt install and never beside a `version`. No download-and-execute form exists, and each command passes through ShouldProcess first. | `install/Deps.ps1`, `core/claude/deps.json` | `install/Install-Harness.Tests.ps1` |
| First-party plugin marketplace identity | A plugin from claude-plugins-official or anthropic-agent-skills is trusted without a commit pin only while that marketplace is registered from its own repository, compared case-insensitively. A registration under either name from anywhere else refuses whatever the plugin's severity, and nothing from it is installed or recorded. | `install/Deps.ps1` | `install/Install-Harness.Tests.ps1` |
| Third-party plugin pin and rollback | A third-party plugin is installed only when its marketplace lists the pinned sha or sits at the pinned commit, and the installed copy is checked against its content hash and commit afterwards. A copy that fails that check, or cannot be checked, is uninstalled and its removal confirmed by a fresh listing. A rollback that fails, is declined or cannot be confirmed stops the run and says the plugin is still installed. | `install/Deps.ps1` | `install/Install-Harness.Tests.ps1` |
| Plugin listing never echoed | The plugin and marketplace listings, which can carry MCP server headers and credential-bearing URLs, are parsed in memory only, and only a JSON array counts as an answer. No message, warning or written file carries their content, and a refusal names the plugin and the field that failed. | `install/Deps.ps1` | `install/Install-Harness.Tests.ps1` |
| Review body identity check | The pull request reviewer refuses a review body, or any string the model wrote, that carries an identifying string (dry runs included), including the email of the logged-in claude account. | `tools/pr-review/identity.ts` | `test/pr-review-identity.test.ts` |
| Reviewer per-repository policy | Verification for a pull request uses only that repository's own required checks and CI workflows. This repository's are built in. Any other repository's come from an operator-held policy file passed with `--policy`. The whole file is refused when it sits inside any git checkout or is malformed at the top level, and an entry is refused for its own repository when it holds an unknown key, an app other than Actions or code scanning, or a workflow path outside `.github/workflows/`. A repository with no valid entry is refused before the App key is read and nothing is posted. A required Actions check counts only when exactly one job, by `name:` or by job id when it has none, reports under its name in its own base-commit workflow. A code-scanning check counts only on a run from that app. | `tools/pr-review/repo-policy.ts`, `tools/pr-review/verdict.ts`, `tools/pr-review/cli.ts` | `test/pr-review-repo-policy.test.ts`, `test/pr-review-verdict.test.ts`, `test/pr-review-cli.test.ts` |
| Reviewer cannot-vouch additions | A repository's policy entry may list extra paths in `cannotVouchAdd`, and an edit to any of them, matched without case, withholds approval. An item without a trailing slash also covers everything under it. The list only adds to the fixed set of CI and secret-scan paths, and an item that is empty, absolute, or holds a backslash, a control character or a `..` segment invalidates the entry. | `tools/pr-review/repo-policy.ts`, `tools/pr-review/verdict.ts` | `test/pr-review-repo-policy.test.ts`, `test/pr-review-verdict.test.ts` |
| Premerge hygiene check | An administrator bypass merge needs a passing `premerge` run on the merged head. The run passes only when the pull request is open with checks green, its closing references are exactly the expected set, every commit was read, no commit message carries a closing keyword, every author and committer equals the expected identity, and neither the commit messages nor the PR title and body carry a term from the operator's list. A missing, empty or malformed list, a list inside a git checkout, a matcher that throws or misses its canary, and a failed GitHub read each block the run. No output carries a matched value or the list's path. | `tools/pr-review/premerge.ts`, `tools/pr-review/cli.ts` | `test/pr-review-premerge.test.ts` |
| Reviewer App permissions | The reviewer stops if its GitHub App holds permissions beyond the allowlist or mints a token wider than one repository. The private key never leaves the process. | `tools/pr-review/app-auth.ts` | `test/pr-review-app-auth.test.ts` |
