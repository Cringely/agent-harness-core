Prebuilt memory engines evaluated, none adopted

Closed

Mem0, Supermemory and swafra were each read at source and skipped. All three resolve a conflict with an accepted decision inside the system instead of handing it to the operator, which is the one requirement the incumbent exists to hold.

  • Mem0 preserves 3 of 15 lifecycle requirements; conflict resolution is the system's, not the operator's
  • Supermemory preserves 0 of 5 checked: closed-source core binary, silent fallback to the vendor's hosted API, no Windows self-host path
  • swafra multiplies retrieval score by a hardcoded exp(-0.005 * days_old) with no pin and no exemption, which contradicts precedence rather than merely omitting it
  • External support: LongMemEval-V2 Small puts files plus agentic search at 0.749 against 0.586 for the best RAG memory pipeline
  • One published figure points the other way and is still unanswered: NOOA reports 38.4% for markdown files against 50.2%, which matters only if its file condition included agentic search

Field census, and the mechanisms worth taking

Measured

All 129 systems in the agent-memory atlas were scored from their own capability frontmatter. That overturned this project's earlier reading that nobody else builds a governed decision ledger.

  • 90% of the corpus holds two or fewer of seven governance capabilities, but two hold six and one holds seven; a system worth learning from lives in that tail
  • Rejection tombstones are held by 4 of 129 systems, and this harness is one of the four
  • Three systems then read at source as harvest targets, not migration targets: Verel, Daimon, TigrimOSR
  • Four mechanisms declined outright: attested promotion gates, hash-chained audit logs, bi-temporal correction chains, a SQLite disposable index

Transition counter built, shipped inert, then switched on

Shipped, zero rows

A PostToolUse hook that counts three kinds of memory-note transition. Written deliberately unwired at 09:46, approved and registered 88 minutes later. It fires correctly under live capture and has recorded nothing from real work.

  • Fail-open by contract: never writes stdout, one stderr line on error, always exits zero
  • Counts only. It does not warn, block, or have an opinion the agent can act on
  • A live run caught it sharding counters per project, which the earlier synthetic check had passed; it now writes one file under the home directory
  • Its own success condition is a month of ordinary use with the file still empty

Positions withdrawn sixteen in the harness work

The highest-signal part of the record and the part most easily lost, because the final state of a file shows the fix and hides that a fix was needed. Eight of the sixteen are shown.

01
Run 1 concluded that retrieval worked while decision compliance failed.
Withdrawn the same day. The hand-written answer key flattened a scoped rejection into a blanket one and dropped the live carve-out on line 29 of the note, so a defensible answer was scored wrong. Experimenter error, not agent error.
02
The answer keys behind the A/B runs were treated as ground truth.
Defective three times across two runs, in the single component that decides every score. Two of four keys in Run 3 were caught only because scorers were told to open the note and overrule the key. Standing rule: build keys by quoting note lines verbatim with file and line, never by paraphrasing.
03
Runs 1 and 2 were understood to be measuring the agent.
Run 3 reclassified both as measuring the note template. Every decision note here carries a revisit clause because the template mandates one, so the failure the runs were built to catch cannot occur in this corpus. Obedience testing closed as unanswerable rather than answered.
04
The counter's storage, sharded per project under the project directory.
Reversed 95 minutes after it shipped. A user-level hook writing per-project shards splits the one question the counter exists to answer, and an empty shard reads exactly like an empty result. One home-directory file now, with absolute note paths.
05
A published line reading "Verified against a synthetic proposed to accepted payload: two correct lines, exit 0, stdout untouched."
Rewritten 132 seconds later to "Verified by live capture through the hook runner, not only by piping a payload at the script." The synthetic check is precisely what missed the sharding bug. This particular retraction exists only in the git diff.
06
The eight-requirement scorecard used to assess the first three candidates.
Conceded as flawed. The requirements were derived from the incumbent's own design, so candidates were scored on resemblance and the incumbent's own row was unfalsifiable. Only one requirement is load-bearing, and harvesting a component was never on the ballot.
07
The reading that nothing in the field builds a governed decision ledger.
Overturned by scoring all 129 rows instead of three samples. It holds for 90% of the corpus and fails at the tail, which is exactly where a system worth adapting would live. This reversal produced the shortlist.
08
A claim to the operator that the repo's master already carried an agent-frontmatter fix.
Master still carries the wrong key in six definitions. The branch renamed four of them and dropped the key from the other two, so the fix exists only on the unmerged branch the working tree happened to sit on. Standing rule: name the branch, or run git show master:<path>, before citing any file as evidence of what ships. The count in this row was itself wrong at first draft, caught by the review pass below.

What this record does not establish

  1. No memory system was adopted and nothing was migrated. The incumbent file-based system is unchanged.
  2. The counter has never recorded a row from real work. One live test proves the hook fires. Zero rows proves nothing about how often agents actually overstep.
  3. The 14-line provisioning section shipped into six agents was never run as written. The A/B tested one line; the shipped text is that line plus three additions.
  4. None of this window's work is merged. The installer would copy none of it into a project today.
  5. The 3-of-8-to-1-of-8 result is not a fleet failure rate. The task set was built so the deciding fact always lived in a note. No base rate for ordinary dispatches exists.
  6. The new frontmatter fields have nothing written against them. No note in 239 uses evidence_tier or accepted_via, so the Lint check that pairs them cannot fire.
  7. The tombstone rules have nothing to be tested against. Exactly one rejected note exists corpus-wide.
  8. The wrap-up cap has never been checked against output. No before-and-after word count was taken, and the figure itself moved from about 150 to about 400 within the hour.
  9. Two thirds of the claims underpinning the recommendation were never audited. Three of four research streams were never adversarially verified either.
  10. Reasoning effort was raised inside the window with no comparison run at either setting.
  11. The companion assessment page carries counts it never reconciles. Its pattern library is 20 documents in two places and 21 in a third, and a count of 14 mechanisms triaged sits beside one of twenty patterns triaged.

Eleven of fifteen recorded gaps are shown. The four omitted are narrower versions of the same point: a benchmark question left open, a per-row accuracy check never run, and two unaudited research streams.

Deliberately not built and what would unblock each

Twenty-two items were declined or deferred. The pattern is consistent: count before enforcing, and do not spend a normalizer on a problem that has not recurred.

  • GatedClaim-keyed rejection tombstones, with a shared normalizer and a question-scope key. The counter recording a real status change or a self-closed revisit. It holds zero rows, and nothing else in the queue gets built until it holds something.
  • GatedA blocking gate on the proposed-to-accepted transition. Recorded recurrences. Designed and left unbuilt: four observations is too thin to justify blocking a write.
  • GatedThe Lint check pairing high confidence against assumption-tier evidence. A backfill. The fields exist; no note uses them.
  • OpenTwo small adopt-queue items: making the secret-scan gate's fail-open direction visible, and giving the contradiction scan a keep-both outcome. Nothing. Two lines and one clause, still outstanding.
  • OpenMerging the branch to master. Nothing stated. Every change in this window sits on one unmerged branch.
  • DeclinedAttested promotion gates, hash-chained audit logs, bi-temporal correction chains, a SQLite disposable index. Scale that does not exist here. The audit log is strictly weaker than git; 239 notes is not a corpus where grep stops answering in milliseconds.
  • UnrunA decisive obedience test. A rejected decision with no live carve-out, a task where the rejected option is genuinely best, and a control arm that exhibits the failure. None of the three exists in this corpus.
  • UnrunThree swafra questions: benchmark spread, ambient-key egress, linear-scan ceiling. Re-running the evaluation at the pinned commit, capturing one request body through a proxy, and timing the scan at 239, 2,500 and 5,000 chunks. Read at source only; no packet captured, no arithmetic run.
