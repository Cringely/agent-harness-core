What every candidate is scored against

Eight requirements, drawn from the governance the incumbent already enforces. Hover any meter cell to read its requirement. A system that stores facts well but inverts requirement 2 is not a near miss; it is a different product.

1 · StatusDecision notes carry proposed / accepted / rejected.
2 · ConflictA conflict with an accepted note is flagged to the human, never silently overridden.
3 · AuthorityAn agent may never mark its own note accepted.
4 · TombstoneRejected decisions stay recorded so they are not re-proposed.
5 · Plain filesHuman-editable, diffable, git-visible. No database required.
6 · ProvenanceOrigin session, updated date, confidence tier on every note.
7 · PrecedenceRules files beat accepted decision notes beat handoff.
8 · TieringEvidence tiers are explicit and recorded with the claim.

swafra Skip

github.com/kunal12203/swafra · MIT · Python + TypeScript · HEAD 669e7bd
Assessed 2026-08-01

1 2 3 4 5 6 7 8
Sits between Supermemory and Mem0: cleaner residency, no better governance.
What decides it Every retrieval score is multiplied by exp(-0.005 × days_old), a 139-day half-life, hardcoded, with no pin, exempt or priority mechanism in the repo. Bolt a status field on and an accepted decision from January still loses monotonically to last week's chatter, because the ranker decays it before precedence ever speaks. Requirement 7 is not unimplemented here. It is contradicted by the ranking function, which is what makes swafra unfixable for this purpose rather than merely unequipped.
Security relevant

The LLM path is gated on a key being present, but the gate reads ambient environment. An ANTHROPIC_API_KEY or OPENAI_API_KEY already exported for unrelated reasons switches swafra to outbound mode, and _llm_rerank is then called unconditionally from get_context, sending stored chunk text to the vendor. This is the one claim of eighteen that the adversarial verifier overturned: "no remote reranker" is false. The code path is read in source; nobody captured a packet, so the honest statement is that the path exists and is ungated, not that memory contents have been observed leaving the machine.

Separately, swafra setup writes to four locations without prompting: two hook scripts under ~/.claude/hooks/, a whole-file rewrite of ~/.claude/settings.json, and an appended block in the global CLAUDE.md. The installed hooks branch on a $TOOL_NAME environment variable that Claude Code does not set. engine/deps.py shells out to pip with --break-system-packages from the server entry point.

StorageJSON at ~/.scimap/{chunks,edges,sources,facts}.json, auto-migrating to SQLite at 5,000 chunks and 500 KB. One way; the documented swafra export back to JSON does not exist.
RetrievalFixed-weight fusion: 0.4·BM25 + 0.15·vector + 0.25·entity + 0.2·trigram, then times the recency decay. Vector carries the smallest weight of the four.
Embeddingfastembed, BAAI/bge-small-en-v1.5, 384 dimensions, local, overridable via SCIMAP_EMBED_MODEL.
GraphFour edge types (sequential, similarity, entity co-occurrence, cross-session), BFS traversal. Leiden community_id is computed and stored, then never referenced in ranking.
ScalingFull linear scan: one cosine per chunk per query in pure Python, BM25 index rebuilt from scratch on every call, and get_context requests k = total chunks.
LLMNot required for ingest or retrieval. All LLM use is gated on a key, and there is no silent vendor fallback of the kind that sank Supermemory.

Measured: does memory provisioning change output?

The first result on this page backed by an experiment rather than a source read. Eight work-shaped tasks, each turning on a fact that exists only in a memory note and not in any rules file or repo. Control got the task exactly as subagents are dispatched today. Treatment got the same task plus one line naming the memory index. Two blind scorers per pair, arm order flipped on alternating tasks.

Retracted: the compliance failure this run reported

This section originally read that the treatment agent found both notes, quoted the accepted Taildrive decision and the recorded SMB rejection, and recommended SMB anyway, and concluded that retrieval worked while compliance failed. A follow-up run sent me back to the source note, and the conclusion does not survive it.

The rejection note carries a live carve-out at line 29: "Revisit when: the desktop moves onto the LAN full-time, direct SMB (LAN, not over Tailscale) becomes viable again." The rejection is scoped to SMB over Tailscale, not to SMB. The agent argued a revisit condition against a note that has one. The ground truth I wrote for that task said the wrong answer recommends SMB, with no carve-out and no scope, so the scorers marked a defensible answer wrong. The experimenter's error, not the agent's.

What this costs: the treatment arm's remaining failure is disputed, so the honest outcome line is 3 of 8 down to somewhere between 0 and 1 of 8. The two prevented failures are untouched by the error and still stand.

The answer key is the least reliable part of this experiment

Two of four trigger keys were wrong this run in ways a scorer had to overrule, and run 1 was retracted for the same defect. Three key errors across two runs, in the one component that decides every score. Scorers were instructed this time to open the note and overrule the key, and that instruction is what caught both. Generate keys by quoting note lines verbatim with file and line, never by paraphrasing.

Shortlist: not yet assessed, ranked by the property that matters

The three candidates assessed at source arrived by circumstance, not by governance fit. Ranking the full 129 by the seven capabilities surfaces a tail that was never looked at. Everything below is a catalog claim at T3, unverified against source, and the honest read is "worth opening," not "better than what we have."

Verel · 7 of 7 The only system holding all seven. Explicit candidate / verified / rejected states with provenance and confidence, and a human adjudicating the promotion from candidate to verified in memory/review.py. The attested gate is built so an approval cannot launder a value the tombstone already rejected, which is requirements 2, 3 and 4 as one mechanism.
Daimon · 6 of 7 Tags every item verbatim or inferred, code-verified against the transcript. Correction is a CLI surface (resolve, forget, reverify) where the destructive act is human-run. Near-file-based: per-project JSON checkpoints are the source of truth and SQLite exists only as a disposable, rebuildable FTS5 index.
Universal Memory Engine · 6 of 7 Candidates cycle pending, promoted, rejected, suppressed with confidence and evidence before becoming a node. Human review is a dashboard over the candidate queue.
TigrimOSR · 3 of 7 The closest architectural cousin in the corpus. JSON files, no database, no embeddings, skill directories on disk, and it still holds trust state, scope enforcement and a human review surface. Scores lower than the leaders but proves the properties do not require a database.
Discount RainBox scores 4 of 7 and is the atlas author's own project, self-assessed and disclosed as such. Core Memory scores 4 of 7 on a grounding-capped confidence class plus an approval workflow recording rejecter and reason.
What this changes The earlier reading that the field is not building a governed decision ledger was drawn from three samples and does not survive the full distribution. It holds for 90% of the corpus and fails at the tail, which is precisely where a system worth adapting would live.

Adopt queue

Four patterns from the atlas survived triage out of twenty; eight were already implemented here and eight need infrastructure this corpus does not justify. Every survivor is a frontmatter field or a line of skill prose. Ranked by value per unit effort.

  1. Key the rejection tombstone on the claim, not the slug

    The write-path check against the rejection ledger already exists, which is the rare half of this pattern. The key is wrong in exactly the way the pattern warns about: the Rejected: index line records a filename slug, so a re-proposal phrased differently never collides and the guard silently misses. Record the rejected claim alongside the slug and match on claim text.

    Cost: one line in the memory-system skill's Decisions index spec, one clause in Lint step 10, plus rewriting the existing entries. No new field, no hook, no schema.

  2. Add metadata.evidence_tier to note frontmatter

    The vocabulary is already written down in no-overclaim.md (live capture, offline test, vendored reference, assumption). It just never became a field, so nothing can check a note's confidence against the strength of what backs it.

    Cost: one row in the frontmatter table, one Lint check flagging confidence: high against evidence_tier: assumption.

  3. Make the secrets-scan gate's fail direction visible

    The scan fails open, which is defensible given the Lint backstop, but the fail is silent. A broken gate currently looks identical to a clean pass.

    Cost: two lines. A comment naming the fail direction and the backstop that justifies it, plus output on the parse-failure path.

  4. Give the Lint contradiction scan a keep_both outcome

    Two notes can disagree because the world changed, not because one is wrong. Without an explicit outcome for that, the scan pushes toward resolving what should stay recorded as a pair.

    Cost: one clause in the skill's step 3.

Carried forward as validation rather than adoption: the atlas's trust-state-machine pattern rates this lifecycle stronger than most of its corpus on requirements 1 and 3. The rule that an agent may never write accepted is the same shape CLIO built, and unlike CLIO's, this one can actually fire.

Method, and where it is thin

Each assessment runs as a multi-agent pass: independent readers over source, an adversarial verifier per load-bearing claim that can only correct tiers downward, then synthesis. Verifiers are briefed that false refutation is itself a known failure mode, because agent-name collisions and summarizer confabulation have previously produced fabrication verdicts against real citations.

The thin part, stated rather than buried. In the 2026-08-01 run only the swafra source stream passed the verifier. The benchmark analysis and both atlas streams are single-agent and unaudited, and the verifier corrected three tiers downward inside the one stream it did check. The earlier 2026-07-31 run had 46 of 142 claims audited at a 30% defect rate, all tier inflation or miscitation rather than fabrication. Weight the unaudited streams accordingly.

One consequence worth keeping visible: two agent-run assessments agreeing is correlated evidence, not independent confirmation. The atlas matching this ledger's ordering on Mem0 and Supermemory raises confidence a little. It does not settle anything.

The failure mode this page has now demonstrated on itself is experimenter-authored ground truth. The A/B's governance conclusion rested on one task whose ground truth flattened a scoped rejection into a blanket one and dropped the revisit clause attached to it. Two blind scorers, working from that text, agreed with each other and were both wrong, which is exactly what blind scoring cannot catch. Anything scored against a hand-written answer key inherits the key's errors, so read the source note before trusting the score.
