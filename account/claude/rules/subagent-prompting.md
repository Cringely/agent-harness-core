# Subagent Prompting

Full guidance lives in the `subagent-prompting` skill. Invoke it before writing any non-trivial agent brief or authoring an agent definition. It carries brief anatomy, context provisioning, the snippet library pointer, per-model effort tables, and the reconciliation notes against Anthropic's per-model docs (last refetched 2026-07-28).

`agent-usage.md` decides when to delegate. The skill decides how to write the brief once you do.

## Resident facts

These stay here because each one fails silently, and a skill that does not get invoked cannot warn you.

- The agent-def frontmatter key is `effort`, not `reasoning_effort`. An unrecognized key is ignored without error, so a typo runs the agent at inherited session effort forever. Six local defs carried the wrong key for months.
- Setting `memory:` in an agent def automatically grants Read, Write, and Edit, overriding a `tools:` allowlist that omits them. An agent that must stay read-only cannot have `memory:` at all.
- A background or teammate agent's plain text output never reaches the dispatcher, so a brief that says "report in your final message" produces an agent that does real work and delivers nothing. The delivery path is an absolute scratch-file path the brief tells the agent to write to, never a `SendMessage` back, which `agent-usage.md` rules out in that direction. Counted three times when this rule was written, five in `agent-usage.md`'s current tally. That file also carries which agent types hold no Write tool and therefore cannot be given a path at all.
- Never surface remaining-context counts or token budgets to an agent. It induces premature self-summarizing instead of finishing the task.
- On Opus 5, delete verification instructions from briefs rather than rewording them. Scope is briefs only. The operational gates in `change-management.md`, `security.md`, and `no-overclaim.md` are untouched. A premise-verification instruction (confirm the claimed defect exists before fixing it) also stays, because it checks the world rather than the model's own reasoning.
- Tool-call arguments are JSON, so an escape sequence typed into a brief, a command, a comment or a file body arrives decoded. A backslash-u escape for a control character is written to the file as the raw byte, with no tool error, and doubling the backslash does not reliably survive either. Where the exact text already exists in a file (a plan, a task brief), tell the agent to extract it by line range and hash-compare, never retype it. Build an escape you author from character codes. Write about an escape in words ("backslash-u 001b") rather than quoting it. Scan committed files, reports and ledgers by numeric code point, not with grep. Recurred across two sessions, 2026-09-11 and 2026-09-14, four times in the second despite every brief carrying the method.
- A dispatched agent is not woken when its own background command finishes. Any brief that may run something past the foreground limit tells the agent to redirect output to a log and poll it in a bounded foreground loop, or to run a narrower test in the foreground instead. When an agent reports it is waiting on a background run, the coordinator messages it rather than waiting on it. The failure runs the other way too: a background call's completion notification reports on the shell the tool started, not on the work, so `nohup ... &` inside it reports done while the real process keeps running. Stalled three times on 2026-09-11 and three more on 2026-09-22, every time in a brief written without this wording, never in the workflow briefs that carried it.
- A verification command pasted into a report can disclose the exact value it was built to search for. A brief that inlined a grep pattern containing identity tokens got that pattern quoted verbatim into a public PR comment (2026-09-19), because the agent was told to show its evidence and the command's own argument text was the secret. Reference the project's scan script or hook by path and ask for the outcome ("scan clean, zero matches"), never the literal pattern. `security.md`'s channel list already covers scanning PR and issue text after the fact. This closes the producer side, the brief that would leak into it.
- A dispatched agent's structured-output field commonly fails JSON validation, and burns the agent's retries to exhaustion, when it carries a regex, a Windows backslash path, or a pasted code line. Five agents died this way between 2026-09-19 and 2026-09-22. Brief every structured-output field explicitly: plain prose, forward slashes only, no regex or code literals, and a character cap per field.
